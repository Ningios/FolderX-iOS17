# FolderX 1.5.16 — 跨页临时显示模型保护（候选版）

## 证据
- v14 抓到 `SBIconListView regenerateTemporaryDisplayedModelIfNecessary` 在跨页拖动期间，将真实 4×2、4×2、2×2 文件夹绑定到 60×74 的临时视图。
- v15 Frida A/B 共两次：定向跳过该方法后，目标页三个文件夹在进入时和 350ms 后均保持原始大尺寸，small=0。
- v15 **只验证了预览阶段**，没有验证正常跨页放置、排序或取消后的恢复；所以本版仍是测试候选，不是完整修复证明。

## 本次源码改动
仅修改 FXDrop.xm（和版本号/文档），**不改** 1.5.12/1.5.14 拖动防上移、1.5.15 文件夹禁止进入开关、内部预览、菜单或开合动画。

普通 App 原生拖动开始前记录来源 `SBIconListView` / listModel。仅当：
1. 原生普通 App 拖动仍处于活动状态；
2. 目标是**不同于来源页**的、当前可见的 `SBIconListView`；
3. 原生模型验证该页恰有 **两个 4×2 和一个 2×2** 文件夹，且 4×6 网格里的每个多格占位均合法、不相交；
4. 来源页和目标页都是完整桌面页面，且没有进入执行放置或拖动结束阶段；
5. SpringBoard 正调用 `regenerateTemporaryDisplayedModelIfNecessary`；
才跳过该次临时模型重建。

其他页面、同页拖动、整个文件夹拖动、**开始放置时立即恢复原生重建**、取消拖动结束、打开关闭文件夹等路径完整调用原生逻辑。**没有更改** `gridSizeClass`、`gridRange`、`modelHasNonDefaultSizedIcons`、`SBIconView.frame`、`setCenter:` 或强制 1×1。

## 目前未解决
- 其他布局组合（只有一个 2×2、一个 4×2 等）仍可能缩小，尚无对应 A/B 证据。
- 文件夹打开/关闭期间的小图标重叠尚未修复；这一版没有修改转场。
- 此改动可能使目标页临时拖放模型不更新，所以**实际拖入并放下**仍需要单独真机验证。若出现拖放失败、重叠、图标丢失或异常，请立即回退 1.5.15，必要时重启 SpringBoard；不要继续反复拖放。

## 先测
1. 先备份桌面布局、保留 1.5.15 包。测试普通 App 同页拖动、大文件夹拖动和“禁止进入”，确认功能不回归。
2. 从其他页面拖 App 进入两个 4×2 + 一个 2×2 的满格页面，**先取消拖动**。观察文件夹是否仍是大尺寸、是否重叠、其他图标是否上移。
3. 如果取消正常，再备份一次并试一回实际放下；确认图标位置与 App 数量、文件夹内部图标数量一致。

静态 QA != Theos 编译 != 真机验证。
