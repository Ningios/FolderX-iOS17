# 1.5.12 — 针对拖动中普通图标进入大文件夹区域的修复候选

## 真机证据（v8）

2 个 4×2 和 1 个 2×2 的满格页面：普通 App 模型始终在 18、19、22、23 格。
但拖动时视图突然被摆到上方 4×2 文件夹的格 2/3/4，对应日志
`modelStableMovedApps=3`，同时 `frame/screen/presentation` 同步移动。
松手前视图又恢复。说明是 *drag visual reflow*，不是模型占格改变。

## 代码改动

- 完全删除无效实验 `FXGridReadPolicy.xm`，不再 Hook `modelHasNonDefaultSizedIcons`。
- 新增 `FXDragAppFrameGuard.xm`。仅在已经开始的原生拖动期间，对当前页面的
  普通 App 视图进行条件判断。捕获的文件夹必须通过原生 gridRange 核实为
  2×2 或 4×2，且必须在同一个实际 `SBIconListView` 中。
- 如果 App 模型仍停在原格，且 SpringBoard 准备把其 *视图* 放入大文件夹
  真实画面占位区域（覆盖面积 >58%），只拒绝这次 `setFrame:` 或
  `setCenter:` 调用，不冻结 App 整个视图、不修改模型、占位符或文件夹。
- 目标不在大文件夹区域、用户确实完成模型换位、跨页/重挂载、文件夹真实
  尺寸发生改变，以及拖动结束后的更新：全部由原生逻辑处理。
- 拖动结束、开始原生 performDrop、拖动异常清理时立刻停用视觉保护。
- 继续保留 1.5.7 以来已验证防止文件夹重叠的布局暂停机制及内部图标变暗。

## 测试注意

静态源代码检查通过不代表越狱环境下已编译 / 真机验证。
此方案使用私有视图类 `SBIconView` 的 `setFrame:` / `setCenter:`；
如果该 iOS 构建从更底层直接修改图层、或父级容器参与重排，则无法拦截。
请备份桌面布局及 1.5.10/1.5.11 安装包后，仅测试一个页面。

1. 编辑模式静置：应不受影响。
2. 拖动普通 App 在三个多格文件夹附近经过：App 应不再临时跳进文件夹区域。
3. 拖动结束，普通 App 应能正常排序；拖入文件夹应能入夹且内部图标变暗。
4. 三个文件夹不可重叠，2×2/4×2 外框和模型格保持不变。
5. 如果不再上移但图标无法正常换位，立即回退，记录现象。

## 局限

没有真实 iOS 17.1.1 SpringBoard 原生 SDK / 硬件用于集成测试。
该修复是针对 v8 捕获的异常视图位移的候选方案，不保证处理所有重排路径。
