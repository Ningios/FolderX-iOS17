# FolderX 1.5.13：四项新问题处理说明

## 已直接尝试修复（仍需真机验证）

**问题 1：拖动大文件夹，其他大文件夹缩成 1×1。** 原先 `FXDrop.xm` 只把普通 App 识别为拖动源。现在识别原生文件夹拖动，启用原有大文件夹图像保护；对正在拖起的文件夹不申请布局暂停，以免阻止移动。没有修改其 `gridSizeClass` 和外框。

**问题 3：从别的页面拖入，当前页大文件夹变小。** 在 `SBIconListView` 原生布局前，以及拖入目标列表更新前，动态补充新进入页面的大文件夹保护。扫描只在原生拖动期间执行。若页面在保护前已被系统压缩，此修复不一定完全生效，需要 v9。

**3D Touch 菜单：** 删除原来的 `小文件夹/2×2/4×2/文件夹大小` 操作，保留原生菜单项目以及编辑模式下右下角滑动调节大小。新增「禁止进入文件夹」开关（有勾选表示已开启）；每个大文件夹独立保存。启用后点空白区域不应打开该文件夹；点缩略网格中的 App 仍可启动。打开与关闭开关不执行任何尺寸修改。

## 需要证据后再修复

**问题 2：打开/关闭时图标重叠。** 原因可能是 `FXMiniGrid` 与原生 `SBFolderIconImageView` 的网格图同时可见，或关闭动画完成时机不匹配。未直接改动画层。用 v9 记录 `miniVisible`、`nativeAlpha`、`pageAlpha` 和 `nativeFrame`。

**问题 4：图标跨页离开又返回时大文件夹重叠。** 本版可能因新增目标页保护而改善，但尚不能确认究竟是文件夹外框、内层图像、还是普通 App 跳位。请用 v9 记录 `FRAME / SCREEN / ANIM / COMPOSITE`。

## 测试顺序

1. 先备份主屏幕布局与 1.5.12 的安装包。确保旧 tweak 已被新 tweak 替换，不要同时启用两个不同版本。
2. 在已验证的满格页面测试**普通 App**拖动，确认 1.5.12 的修复仍然有效。
3. 在同页拖动一个 4×2 大文件夹，确认其他文件夹是否保持原尺寸且拖动源正常移动。
4. 从另一页面拖普通 App 进入该页面，停留约 1 秒，再回到原页面和再次进入，观察是否缩小或重叠。
5. 长按大文件夹测试菜单：只有「禁止进入文件夹」开关，没有尺寸菜单。开启后点文件夹空白区域无法进入，但可点内部 App；关闭后可正常进入。右下角滑动调尺寸依旧可用。
6. 单独测试打开/关闭。若有重叠，先恢复 1.5.12 或运行诊断，不要重复快速测试导致布局状态更乱。

## v9 只读诊断脚本

Mac：将 `folderx_newbugs_readonly_v9.js` 放到 Downloads。iPhone 运行与电脑兼容的 frida-server。终端执行：

```bash
frida -U -n SpringBoard -l ~/Downloads/folderx_newbugs_readonly_v9.js
```

成功时看到 `=== FOLDERX NEW BUGS TRACE v9.0 ===` 和 `[FXNEW9] READY`。每次**只测试一种**：A 拖动大文件夹；B 打开/关闭；C 跨页出入。测试之间退出 Frida 重新加载脚本。分享 `[FXNEW9]` 行。

该脚本仅观测方法回调、图层、原生网格和视图坐标，不改写返回值、不改尺寸、不保存 App 标识。

## 构建说明

这是供 Theos 工程使用的完整源码；本环境没有真实 iOS SDK/设备，**没有进行 Theos 编译和真机测试**。工程静态检查通过不等于已解决所有问题。建议仅在可恢复的测试布局上安装。
