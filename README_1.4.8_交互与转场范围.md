# FolderX 1.4.8：开合转场时序防护候选版

## 新上传的 Frida 拖动占格结果
- 这次完整拖动里，7 个文件夹中的 4 个大文件夹在 before-drag / begin / placeholder / perform-drop / end 均保持真实 2×2。
- `ADD PLACEHOLDER representing=SBApplicationIcon` 属于普通 App 的拖动占位回调，并不表示文件夹变为 1×1。
- `placeholders=0` 是探针特定层面的取样，不能用它否定日志中的占位创建事件。
- 因而**这次不改变尺寸模型、真实占格与拖入实现，也不新增扩大命中区**。

## 本版可从源码确认的具体修正
`FXTransition.xm` 中，`SBHIconManager` 的 `_folderDidFinishOpenClose:animated:success:` 同时处理 opening/closing。1.4.7 在关闭待决时把任意回调都当作关闭完成；1.4.8 只有 `opened == NO` 时才完成关闭。这能阻止“打开完成回调误释放关闭状态”的竞态。

## 仍未解决、不可冒充完成
- **不保证**已完全修复用户看到的开关文件夹时图标叠影；还可能来自 `SBFolderIconImageView` 复制/重建、`FXMiniGrid` 与原生预览同时可见。
- **不保证**已有的拖入是完整系统原生飞入动画。1.4.7 仍含异步原生 manager 补救调用（及 0.55 秒兜底），不能仅靠显示动画消除实际提交顺序差异。
- 本版只是缩小一条已确认的时序缺陷，**不改**现有已可用的 2×2、4×2 手势与拖入行为。

## 验收
1. 备份原插件、桌面布局、保留 1.4.7 DEB 以便回退。
2. 在留有空格的测试页连续打开/关闭同一个大文件夹 5 次，然后打开/关闭相邻文件夹。观察有无缩略图闪现/图标重叠。
3. 拖一个普通 App 进入 2×2 文件夹，核实 App 实际入夹，检查之前已经成功的尺寸切换。
4. 如仍有叠影/回弹，继续针对“原生缩略图层 vs 自绘网格层”做针对性转场修复，不增加静态背景快照。

## 验证边界
源码静态检查和补丁还原检查不等于 iOS 17.1.1 真机验证；未在本环境进行 Theos 编译或 SpringBoard 运行测试。
