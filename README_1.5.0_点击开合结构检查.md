# FolderX 1.5.0 — 点击与开合结构修订候选

## 来源与范围

对照用户提供的 FolderExpand 0.3.3、FolderX 1.4.9 源码。0.3.3 `FEOverlayManager.mm` 指出了父级 alpha=0 导致的缩略图闪烁，但其长期挂在 SBIconView 并在菜单预览期间移动图层的设计不宜整段照搬。

本次**只改** FXInterface.mm 里点击防重复与开合图层所有权；FXTransition.xm 更新注释；尺寸模型、编辑手势、FXDrop.xm、FXListHit.xm 不改。

## 从源码确认的结构问题

- 1.4.9 `FXPrepareNativeFolderOpen()` 在原生 open 发生**之前**把九宫格从 `SBFolderIconImageView` 搬到 `SBIconView`。但 SpringBoard 的原生预览/开合动画仍可能以 `SBFolderIconImageView` 为源。因此动画预览、桌面可见九宫格在两个父视图下产生不一致，能够解释重叠、开合时小九宫格闪现。
- `FXRefreshIconView()` 在 `transitionOwner` 下再次把九宫格移动到宿主；当 native layout 反复刷新时，动画前后的坐标系/父层 alpha 变化可能导致不连贯。
- `FXRecentlyHandled()` 用 0.48s 主机级抑制，在一次点击后快速点另一个内部 App 可能被误拦。

## 修改思路

1. 自绘网格在常态和开合期间**只属于同一个 `SBFolderIconImageView`**，不开合前移出、不增第二份视图或快照。原生动画应从包含放大图标的原生图像树获取内容。
2. 原生打开期间只冻结该文件夹原有的网格布局（避免重新计算单元）；结束后解除冻结。原生缩略图隐藏路径不改变。
3. 单独记录上一次点击的内部 App 身份，同一次点击的后续 `_handleTap`/`performTap` 仍被抑制，但快速点**另一个**内部 App 时不再因为 0.48s 守卫无条件被忽略。
4. 取消打开的兜底超时从 0.65s 放宽到 1.5s，降低较慢转场时提前恢复布局的概率；仍属兜底而不是动画时序控制。

## 风险和验收

本版只完成源码静态检查及打包，不代表通过 iOS 17.1.1 真机或 Theos 编译。SpringBoard 可能用内部快照/不同转场路径，不能保证完全没有开合叠影。

需要测试：
- 2×2 / 4×2 文件夹内点 App，直接启动、不额外弹出原生文件夹；快速依次点击不同图标无漏点。
- 点空白进入原生文件夹、关闭；连续 5 次，观察是否双层九宫格、闪小、残影或背景透出。
- 长按显示原生菜单和预览；菜单消失后九宫格位置正常。
- 最后才检查拖入仍能正常成功；本次**没有**修复编辑模式占位或拖入吸入动画。

出现 SpringBoard 重启或图标错乱时回退 1.4.9。请备份旧安装包与桌面布局。
