# FolderX 1.5.5 — 回退整页 Hook，保留拖入能力（测试候选）

## 本次依据

- 用户在 1.5.4 录屏中观察到：开始拖一个普通 App，大文件夹内容消失、周围普通图标大范围跳动，正常拖入无法接受这种 UI 干扰。
- 用户的 Frida V2 日志此前确认：2×2 文件夹模型在拖动中保持 2×2，外层 SBIconView 却偶尔从 158×172 变为 60×74；4×2 有类似现象。系统重排与自绘预览不是一回事。
- 1.5.4 新增的 `SBIconListView.modelHasNonDefaultSizedIcons` getter/setter Hook 与占位符 Hook 是整页级干预，可能放大或触发该类冲突；录屏和差异足以支持**优先回退**，尚不能证明它是唯一原因。

## 源码变化（从 1.5.3 出发）

1. `FXDrop.xm`: 在有效第二次拖动开始前执行 `FXClearSource()`，释放上一轮的 per-icon 暂停断言、视觉锁、目标缓存。这一步发生在下一次网格/目标捕获**之前**。
2. `FXInterface.mm`: `setDropHovered:` 只清除以前的脉冲动画、把边框宽度置零；不绘制蓝色光圈或呼吸灯。
3. **彻底不安装** 1.5.4 新增的 `FXNativeDragGridPolicyHooks`（涉及 `modelHasNonDefaultSizedIcons`、`setModelHasNonDefaultSizedIcons:` 和两个 `addPlaceholderAtGridCellIndex:` Hook），不强改全页布局状态。
4. 恢复 1.5.3 的 `pauseLayoutForIconView:forReason:` **单图标保护**，只为真实多格文件夹申请断言，拖动结束后释放。它可能帮助维持图像位置，但**不能当成占格的修复**。
5. 保留 1.5.3 已存在的 4×2 完整宽度命中、拖入后原生 manager 兜底、模型尺寸和 2×6 图标显示。

## 没有修复的内容

- 周围普通 App 拖动时可能进入文件夹的模型网格区域；需要精确核对 SpringBoard 拖动重排使用的 gridCellIndex / gridRange 与占位符转换，在此之前**不拦截、不伪造、不修改**网格单元位置。
- 打开/关闭文件夹内部图标重叠：本版没有更改转场链。
- 完整原生拖入动画：原生 `%orig` + manager 修复并不等同于原生吸入预览。

## 手工验证顺序

1. 先备份桌面布局和 1.5.3 / 1.5.4 安装包，在测试页安装本版。
2. 连续两次分别拖到 2×2 文件夹附近，观察是否仍发生 1.5.4 那样的整页乱跳与内容消失。
3. 连续两次拖到 4×2 文件夹附近，测试左、中、右三处能否正常成为入夹目标。
4. 尝试拖入一个 App，确认它确实进了文件夹、不重复、不造成布局错位；确认无 FolderX 蓝色光圈。
5. 如果普通 App 仍挤进大文件夹实际格子，记录现象，但**不要认为此版已解决占格问题**。

## 风险和构建

此包是源码，不是可直接安装的 DEB。需要用户 Mac 上的 Theos + iOS 17 SDK。原工程默认为 `THEOS_PACKAGE_SCHEME=roothide`，必须与手机实际越狱方案匹配。SpringBoard 私有接口有设备差异，可能闪退或扰乱图标布局；建议在备份后试验，异常立刻回退。仅完成静态检查、压缩包比对，**没有**在本环境编译或于用户设备验证。
