# FolderX 1.5.3 — 4×2 拖入和占位定点修订（候选）

## 为什么不是“代码只支持 2×2”？

1.5.2 的 FXCore/FXDrop 已经承认 `FXFolderSizeWide = 2`、真实 `4×2` 网格范围，而且预拖命中矩形使用全部 `338×158 pt` 可见区域。并非完全没有实现 4×2。

但 1.5.2 的拖动路径有几个薄弱点：

1. `FXSetDragVisualLockForHost` 在定位到 **内部** `SBFolderIconImageView` 后，才会调用 `FXAcquireDragLayoutPause`。如果宽文件夹内部视图此时缺失或重建，**外层图标布局暂停也不会申请**，导致屏幕仍把 4×2 视图排成 `60×74 pt`。
2. `FXFolderAtDropLocation` 松手时优先用**已经重排中的实时视图**寻找目标；此前的真机日志出现宽文件夹临时变成 `(0,0)` 和 `60×74`，此时可能误认或漏认目标。预拖阶段已经有真实 4×2 模型验证过的缓存矩形，针对宽文件夹应优先使用它。
3. `iconAtPoint:index:` 若原生返回了旁边的其他文件夹，旧代码一概停止重映射；只有经过预拖真实 4×2 验证的命中区域，才应允许纠正此情况。
4. 目标文件夹超过 9 个 App 时，`allIcons` 在某些系统版本可能不完整，去重检查应先枚举所有原生页面。

## 本版做的局部修订

- **FXInterface.mm**：将外层 `SBIconView` 的原生布局暂停与内层缩略图视觉锁彻底分开。先依据真实 2×2／4×2 校验尝试暂停布局，然后再可选锁定内部图像。接口返回/参数 ABI 不匹配时跳过，保留系统默认行为。
- **FXDrop.xm**：完整保存预拖目标的 `sizeClass`；对经过验证的宽文件夹优先使用预拖缓存目标矩形，不再让重排中的临时小图标或 `(0,0)` 视图优先接管命中；只有在已验证的宽文件夹范围内才允许覆盖系统误认的其他文件夹。
- **FXDrop.xm**：宽文件夹的原生页面枚举用于入夹结果去重，防止第 10～12 个 App 被误认为尚未加入。
- 旧 2×2 松手目标查找仍为实时优先；原有 `%orig`、经理补救、图片视觉锁和撤销流程保留。

## 未触碰

`FXCore.mm`、`FXListHit.xm`、`FXTransition.xm`、`Tweak.xm`、`FXMenu.xm`、尺寸设置手势均保持 1.5.2 原样。开合叠影问题仍然没有修复。

## 重要限制

这不是已验证的 4×2 真机修复：用户此前提供的 V2 日志来自旧版逻辑，无法直接证明 1.5.3 的布局暂停一定成功。它使用私有 SpringBoard 接口，只通过源码静态检查、补丁和归档检查，未在本环境 Theos 构建或 iOS 17.1.1 运行。建议备份布局，在测试页优先测试 4×2 左、中、右三个落点，同时确认 2×2 未回退。
