在编辑/拖动模式中，有普通图标出现于大文件夹视觉覆盖区域附近，不能仅用“网格始终 2x2”的 Frida 结果解释；真实网格尺寸检测和临时重排/占位反馈是两个不同层面。按照用户要求，**本版暂不修改占位/重排代码**，等开合验证通过后单独处理。

# FolderX Fresh 1.4.7 — 开合转场 / 拖动缩小 / 原生入夹时机专项

基于 **FolderX 1.4.6 Drag Candidate** 完整源码逐项修改；作者、包 ID、原有 1×1 / 2×2 / 4×2 模型尺寸及 4×2 内部两行六列显示保持不变。

**状态：未经 Theos 编译和 iOS 17.1.1 真机验证的候选源码。不能称为已彻底修复，更不能保证与苹果原生拖入动画逐帧相同。**

## 已经由用户 iOS 17.1.1 / Frida 16.1.4 对比日志确认的事实

- 1×1 正常拖入：SpringBoard 在 `[DRAG] end` **之前**执行 `SBFolder.insertIcon`。
- 1.4.6 大文件夹拖入：原生 `performDrop` 结束，`[DRAG] end` **之后**，才调用 `SBHIconManager addIcons:intoFolderIcon:openFolderOnFinish:completion:`。
- 用户确认 1.4.6 **最终确实成功入夹**：但 App 先回桌面，稍后突然消失；拖动过程中大文件夹会视觉缩小。
- 日志未证明原生文件夹实际从 2×2 / 4×2 改成 1×1，因此不能根据外观变化写入系统图标模型。

## 本次代码变更

1. `FXDrop.xm`：拖动开始之前，从当时有效的扩展文件夹视图捕获视觉状态并锁定；它与严格验证真实占格的**拖放目标缓存分开**。拖动结束后释放视觉锁，**不修改** SBIconView 的模型大小或真实占格。
2. `FXInterface.mm`：遇到系统生成拖拽占位符、原生 `SBFolderIconImageView` 临时缩小时，只恢复**原生图像视图**本次拖动前的尺寸，保持 3×3 / 2×6 自绘图标可见。没有创建背景快照、复制视图、第二个 UIDropInteraction 或新的数据模型。仅在确实捕获到可靠放大视图时生效。
3. `FXDrop.xm`：永远先运行 `%orig` 原生 drop；在返回**下一次主线程循环**优先检查原生是否已经入夹，尚未入夹且源 App 仍在根列表时，通过用户 Frida 已验证存在的原生 manager 方法尽早移入。同一个拖动 generation 只提交一次；若早期 SpringBoard 仍用占位符，0.10 秒重试，并保留 1.4.6 的 0.55 秒最后兜底，避免牺牲已成功的入夹能力。此改动**旨在改善**动画衔接，不承诺完全复用原生预览终点动画。
4. `FXInterface.mm` + `FXTransition.xm`：按实际打开文件夹身份管理显示；**点击时不再提前切出原生 1×1 缩略图**，避免打开的第一帧闪小；关闭后恢复延至 `SBHIconManager._folderDidFinishOpenClose:...` 与控制器离场都完成。仅为丢失的回调增加安全超时兜底。相邻文件夹不受全局展示状态牵连。
5. `FXInterface.mm`：在原生允许的拖放候选上采用轻微的蓝色系统风格描边呼吸作为悬停反馈，不缩放整个文件夹，不增加大小文字。

## 安全边界

- 仅调整临时**可见** `SBFolderIconImageView.frame`，绝不强改 `SBIconView.frame`、首页数据库或 SBIconListModel 占格。
- 对普通 1×1 文件夹、文件夹拖动源、多选图标拖动均不执行特殊入夹补救。
- 每次补救先验证当前文件夹身份、源 App 确实仍在主屏幕根列表以及目标文件夹尚未包含该 App。
- 如果原生系统无法在这个目标提供 drag-preview destination，仍可能看到不完全一致的收纳动画；该能力需要设备上的下一轮实际验证，不能靠伪造一张动画图片来宣称完成。
- 使用到 SpringBoard 私有接口，任何版本都可能因其他插件兼容性产生闪烁、SpringBoard 重启或桌面重排风险。**必须备份桌面布局和旧 DEB**。
